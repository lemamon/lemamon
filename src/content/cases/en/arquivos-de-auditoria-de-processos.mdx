### Who it is for

The system was designed for the quality team of a large manufacturer. That team looks after the files related to process audits, and the system exists to support it in organizing and managing those files.

### How it works

A process audit checks whether a process is carried out the way it was defined. The files related to these audits are what the system helps organize and manage.

The team uses the system's interface (the front end) to organize and manage these files. The interface relies on the back end, the part that runs on the server and answers its requests.

### What was built

- The front end, the interface through which the quality team organizes and manages process audit files.
- The back end, the part of the system that runs on the server and supports the interface.

### The technology, in plain words

- **AngularJS**: a JavaScript framework for building web interfaces that run in the browser; in this system, it is the base of the front end.
- **JavaScript**: the programming language of the web, which gives pages behavior in the browser and also runs on servers; here, it is in both parts of the system.
- **LoopBack**: a Node.js framework for building APIs, the doorways through which the interface requests and receives data from the server; in this system, it is the base of the back end.
