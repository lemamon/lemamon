## 3.1 Auditoria visual do estado atual

### 3.1.0 Resumo executivo do diagnóstico

O site **não tem um design system**. Tem 20 arquivos `styles.ts` independentes, cada um reinventando cor,
espaçamento, sombra e transição. Não existe um único arquivo de tokens, nenhum `ThemeProvider` do
styled-components é instanciado (`grep -r "ThemeProvider" src` → zero ocorrências), e o `createGlobalStyle`
em `src/styles/styles.ts` só cobre 8 seletores de elemento.

O resultado prático para o objetivo de negócio: **o site parece um template**. E parece um template porque
literalmente é um — a estrutura `ContentBlock` / `MiddleBlock` / `Fade direction` com ilustrações flat
(`developer.svg`, `graphs.svg`, `product-launch.svg`, `waving.svg`) é o boilerplate `react-landing-page`.
Um comprador técnico (CTO, head de produto) reconhece o template em 3 segundos e a credibilidade cai antes
do primeiro parágrafo ser lido.

### 3.1.2 Tipografia

#### Carregamento

```
src/styles/styles.ts:5-15
@font-face { font-family: "Motiva Sans Light"; src: url(".../Motiva-Sans-Light.ttf") format("truetype"); }
@font-face { font-family: "Motiva Sans Bold";  src: url(".../Motiva-Sans-Bold.ttf")  format("truetype"); }
```

Cinco problemas:

1. **Peso modelado como família.** `Motiva Sans Light` e `Motiva Sans Bold` são duas famílias distintas em
   vez de uma família com `font-weight: 300` e `700`. Consequência: `font-weight: 600` em
   `src/styles/styles.ts:80` (`h1`) e `src/components/Header/styles.ts:65,109` aciona **faux bold** —
   o navegador engorda sinteticamente uma fonte que já é Bold. O peso visual dos títulos está errado
   em todo o site.
2. **Formato `.ttf`.** 63.460 e 64.504 bytes. Em `woff2` seriam ~28 KB cada — economia de ~70 KB no caminho
   crítico de renderização.
3. **Sem `font-display`.** Default é `auto` → FOIT (texto invisível) de até 3s em 3G.
4. **Sem `<link rel="preload">` em `index.html`.** As fontes só começam a baixar depois que o CSS-in-JS
   é injetado pelo JS. Em `index.html` não existe **nenhum** `<link>` de recurso (linhas 4-28) — só metas.
5. **Fallback errado.** `font-family: 'Motiva Sans Bold', serif` em `src/styles/styles.ts:60` e
   `src/components/Footer/styles.ts:145`. Se a fonte falhar, todos os títulos viram **serifada**
   (Times New Roman). O fallback de uma sans deve ser uma sans stack.

#### Fonte fantasma

```
src/components/Header/styles.ts:107
font-family: "Barriecito Regular", serif;
```

Não existe `@font-face` para `Barriecito Regular` em lugar nenhum (`grep -rn "Barriecito" src` retorna
apenas essa linha). O componente `Logo` — o **logotipo textual** — renderiza em Times New Roman.
Adicionalmente, `public/assets/fonts/Delicious/` é um diretório **vazio**, resíduo de uma tentativa anterior.

#### Escala tipográfica: não existe

```
src/styles/styles.ts:54-71
h1, h2, h3, h4, h5, h6 { font-size: 36px; line-height: 1.18; }
```

`h1` até `h6` têm **o mesmo tamanho**. E o site usa `<h6>` como título de seção em todos os lugares:

- `src/components/ContentBlock/index.tsx:64` → `<h6>{t(title)}</h6>`
- `src/components/Block/index.tsx:14`
- `src/components/MiddleBlock/index.tsx:35`
- `src/components/ContactForm/index.tsx:92`
- `src/components/QuestionItem/index.tsx:63`

**A home não tem `<h1>`.** O título "Soluções Tecnológicas Personalizadas para o Seu Negócio"
(`src/locales/pt-BR/translation.json:51`) é renderizado como `h6`. Para SEO isso é perda direta de ranking;
para leitor de tela, a árvore de headings é `h6, h6, h6, h6, h6` — navegação por landmarks inutilizada.
Para design, significa que **não há hierarquia visual**: hero, seção e subseção têm 36px.

### 3.1.6 Motion

| Declaração | Arquivo:linha |
|---|---|
| `all 0.3s ease-in-out` | `styles.ts:43`; `Button/styles.ts:20`; `ScrollToTop/styles.ts:16`; `Header/styles.ts:95`; `Footer/styles.ts:61,77` |
| `all 0.2s ease-in-out` | `Footer/styles.ts:23,56` |
| `all 0.1s ease-in-out` | `Footer/styles.ts:97,155` |
| `color 0.2s ease-in` | `Header/styles.ts:72` |
| `transform 0.3s` | `src/pages/Blog/index.tsx:30` |

Cinco durações, quatro curvas. Problemas concretos:

- **`transition: all`** em 10 dos 11 casos. Anima também `width`, `height` e `box-shadow`, forçando
  layout/paint a cada frame. Em `src/components/Footer/styles.ts:97` o `FooterContainer` tem
  `transition: all 0.1s` e filhos com `transform: scale(1.1)` — o `all` faz o navegador vigiar
  ~200 propriedades por elemento.
- **Declaração duplicada**: `src/components/Footer/styles.ts:56` declara `transition: all 0.2s ease-in-out`
  e a linha `:61` do **mesmo bloco** declara `transition: all 0.3s ease-in-out`. A segunda vence; a
  primeira é código morto.
- **`ease-in`** em `Header/styles.ts:72` é a curva errada para hover: começa lento e acelera, ou seja,
  o feedback parece atrasado. Hover pede `ease-out`.
- **Zero `prefers-reduced-motion`.** As animações de entrada (`react-awesome-reveal`: `<Fade>` em
  `ContentBlock/index.tsx:52`, `<Slide>` em `Contact/index.tsx:15,20` e `MiddleBlock/index.tsx:31`)
  disparam para todo mundo, inclusive usuários com sensibilidade vestibular declarada no SO.
- `react-awesome-reveal` (32 KB no chunk `react-awesome-reveal.esm-*.js` do build commitado) é uma
  dependência inteira para fazer o que `IntersectionObserver` + 12 linhas de CSS fazem.

### 3.1.7 Bugs de CSS que afetam o visual (e ninguém viu)

Três regras em `src/styles/styles.ts` **nunca aplicam**, por causa de como o stylis (compilador do
styled-components v5) trata aninhamento sem `&`:

```
src/styles/styles.ts:38-52
input, textarea {
    ...
    :focus-within {              ← compila para "input :focus-within" (descendente!)
        background: none;
        box-shadow: #2e186a 0px 0px 0px 1px;
    }
}
```

`<input>` é um elemento void — não tem descendentes. **O focus ring dos formulários nunca aparece.**
O correto seria `&:focus`.

```
src/styles/styles.ts:83-91
a {
    color: #2E186A;
    :hover { color: #2e186a; }   ← compila para "a :hover", também morto
}
```

O hover que de fato acontece é o da linha `:34-36` (`a:hover { color: #18216d }`), que aplica uma cor
**diferente** da que o autor escreveu na linha 89. O comportamento de hover dos links é acidental.

E o mais grave:

```
src/styles/styles.ts:93-95
*:focus { outline: none; }
```

Remove o indicador de foco de **todos os elementos do site**, globalmente, sem substituto — e como o
substituto pretendido (o `:focus-within` acima) está morto, **navegação por teclado é impossível**.
Falha direta de WCAG 2.1 SC 2.4.7 (Focus Visible). Para um comprador corporativo com requisito de
acessibilidade, isso é reprovação em auditoria.

### 3.1.8 Ativos e ícones

`ls public/assets/img/svg`:

```
graphs.svg (22 KB)   linkedin.svg              logo.png (16 KB)       logo.svg (197 B)
```

**`src/common/SvgIcon/index.tsx`** — o componente que renderiza 100% da iconografia:

```tsx
1  export const SvgIcon = ({ src, width, height }) => {
5    const [iconSrc, setIconSrc] = useState<string | null>(null);
7    useEffect(() => { setIconSrc(`${basePath}assets/img/svg/${src}`); }, [src]);
13   return iconSrc ? <img src={iconSrc} .../> : <span>Loading...</span>;
```

- Usa `useState` + `useEffect` só para concatenar uma string. Garante **dois renders** e, no primeiro,
  o texto literal **"Loading..."** — em inglês, fora do i18n — aparece na tela. No header
  (`Header/index.tsx:63`) isso significa que a primeira coisa visível do site é a palavra "Loading...".
- Renderiza `<img>`, então os SVGs **não podem ser recoloridos** via `currentColor`. É por isso que
  `src/components/Footer/styles.ts:124` tenta `&:hover { fill: #ff0000 }` num `div` que contém um
  `<img>` — **a regra não tem efeito nenhum**.
- Não passa `loading`, `decoding`, `width`/`height` intrínsecos → CLS em cada ícone.
- `vite-plugin-svgr` está no `package.json` como dependência e **nunca é usado** (`grep -rn "svgr" src`
  → zero). Dependência morta que resolveria exatamente esse problema.

**Logo inconsistente entre header e footer:**

- `src/components/Header/index.tsx:63` → `logo.png` (raster, 16 KB) a `width="70%"` — borrado em retina,
  dimensão relativa causa reflow.
- `src/components/Footer/index.tsx:117` → `logo.svg` (197 bytes).
- E `public/assets/img/svg/logo.svg` é literalmente um `<text font-family="Motiva Sans Bold" fill="#18216d">`.
  Um SVG carregado via `<img>` roda em documento isolado e **não enxerga o `@font-face` da página** —
  logo, o wordmark do footer renderiza numa fonte de sistema arbitrária. **O logotipo do site é diferente
  do logotipo do site.**

**Ilustrações:** `developer.svg`, `graphs.svg`, `product-launch.svg`, `waving.svg` são o pacote
flat-illustration genérico (estilo unDraw/Storyset), o mesmo usado por milhares de landing pages.
`notes.svg` é reusado para **as duas** colunas da seção "Sobre"
(`src/locales/pt-BR/translation.json:37` e `:42`) — o mesmo ícone duas vezes, lado a lado.

**`contact-us.png` (287 KB)** é servido a `width="100%"` em `src/components/Contact/index.tsx:22`.
Sem `srcset`, sem WebP/AVIF, sem lazy. É o maior ativo do site e provavelmente o elemento LCP da
seção de conversão.

**`twitter.svg`** existe mas não é referenciado em lugar nenhum. `brasil.svg` tem **32 KB** — uma bandeira,
maior que as três ilustrações de ícone somadas; não foi otimizado (SVGO reduziria para ~2 KB).

`index.html` não tem `<link rel="preload">`, `<link rel="preconnect">` nem `<link rel="canonical">`
(linhas 4-28); tem `og:url` duplicado (`:16` e `:22`), `og:locale = "en_EN"` num site em pt-BR

## 3.2 Diagnóstico: antd v4 + styled-components v5

### 3.2.1 O que está acontecendo

```
src/index.tsx:3
import "antd/dist/antd.css";
```

Uma linha, três consequências.

**Custo de bundle — números do build commitado (`dist/assets/`, build de 17/out/2024):**

| Artefato | Bytes |
|---|---|
| `index-CqbPTlw8.css` | **557.887** (~545 KB) |
| `index-D77bKVHM.js` | **388.899** (~380 KB) |
| `react-awesome-reveal.esm-*.js` | 32.547 |

O CSS de 545 KB é **essencialmente o `antd.css` inteiro**. O CSS autoral do projeto — a soma de todos os
`styles.ts` — não passa de ~8 KB. Ou seja: **~98,5% do CSS entregue ao usuário é de componentes que
o site não usa** (Carousel, Calendar, DatePicker, Transfer, Tree, Cascader, Mentions, Upload...).

CSS é render-blocking. 545 KB de CSS em 4G brasileiro (~3 Mbps efetivos) = ~1,5s só de download antes
do primeiro pixel. Isso é penalidade direta de Core Web Vitals e, portanto, de ranking e de conversão.

**Superfície antd realmente usada** (`grep -rn 'from "antd"' src`):

| Componente | Onde |
|---|---|
| `Row`, `Col` | `ContentBlock/index.tsx:1`, `Footer/index.tsx:1`, `Contact/index.tsx:1`, `MiddleBlock/index.tsx:1`, `Header/index.tsx:2`, `ContentBlock/styles.ts:1` |
| `Drawer` | `Header/index.tsx:2` |
| `Card` | `ContactForm/styles.ts:2`, `QuestionItem/styles.ts:2` |
| `Result` | `ContactForm/index.tsx:5`, `NotFound/index.tsx:1` |
| `Layout` | `Post/index.tsx:3`, `NotFound/index.tsx:1`, `Blog/index.tsx:5` |
| `Tag`, `Typography`, `Alert`, `Table`, `Checkbox` | `Post/index.tsx:3` |
| `notification` | `common/utils/useForm.tsx:2` |

**`Row`/`Col` são ~70% do uso e são apenas um grid flex de 24 colunas.** Isso é substituível por
CSS Grid nativo em ~30 linhas. `Layout` é usado só para desestruturar `Content`, que renderiza uma `<div>`.

**O segundo vazamento, no JS:**

```
src/common/Icon/index.tsx:1
import * as AntIcons from "@ant-design/icons";
```

Namespace import com lookup dinâmico (`AntIcons[iconKey]`, linha 9). Isso **destrói o tree-shaking**:
o bundler não consegue provar quais ícones são usados e inclui os ~800 do pacote. É a causa provável
de boa parte dos 380 KB do chunk principal — para renderizar os poucos ícones do questionário
(`src/pages/Projects/data.json`).

**Override de estilo — o atrito na prática:**

```
src/components/ContactForm/styles.ts:4   export const FormCard = styled(Card as any)`...`
src/components/QuestionItem/styles.ts:4  export const StyledCard = styled(Card as any)`...`
src/components/ContentBlock/styles.ts:13 export const StyledRow = styled(Row as any)`...`
```

O `as any` repetido é o sintoma: os tipos do antd v4 foram escritos para React 17
(`package.json` tem `@types/react: ^17.0.68` com `react: ^18.3.1` — incompatibilidade declarada) e
não compõem com `styled()`. Cada override custa um cast que desliga o type-checking do componente inteiro.

E quando o cast não basta, o projeto desce para o global:

```
src/styles/styles.ts:101-110
.ant-drawer-body { display: flex; flex-direction: column; text-align: left; padding-top: 1.5rem; }
.ant-drawer-content-wrapper { width: 300px !important; }
```

Uma folha global alcançando classes internas de vendor, com `!important`. É o pior padrão possível:
acopla o código a detalhes de implementação de uma versão específica do antd, e qualquer upgrade quebra
silenciosamente (visualmente, sem erro de build).

**Conflitos de reset invisíveis:** o `antd.css` traz o próprio normalize com `body { font-size: 14px;
font-family: -apple-system,... }` e `h1..h6 { margin-bottom: .5em; font-weight: 500 }`. Isso compete
diretamente com `src/styles/styles.ts:18-22` e `:54-77`. Quem vence depende da **ordem de injeção**:
`antd.css` entra no `<head>` no import (`index.tsx:3`), o `createGlobalStyle` é injetado pelo
styled-components em runtime (`src/router/index.tsx:19`) — depois, portanto ganha. Mas isso é
acidental, não projetado. Em SSR ou com mudança de bundler a ordem inverte e o site muda de aparência.

**Sem theming:** não há `ConfigProvider` nem build LESS customizado. As variáveis do antd
(`@primary-color: #1890ff`, `@border-radius-base: 2px`, `@font-size-base: 14px`) estão congeladas
no default. Por isso o azul `#1890ff` e o raio `2px` aparecem no funil de conversão (§3.1.1).

### 3.2.2 Recomendação: **REMOVER** — em duas etapas, encapsulando primeiro

Não é "manter". Manter significa aceitar 545 KB de CSS, um azul de marca alheio no funil de conversão,
`!important` em classes de vendor e uma dependência em modo manutenção travada em React 17 typings.

Não é "só encapsular" como destino final. Encapsular (via `ConfigProvider` + `prefixCls` + CSS-in-JS)
resolveria o conflito de cor, mas exigiria migrar para **antd v5**, que traz um runtime CSS-in-JS próprio
(`@ant-design/cssinjs`, ~40 KB) rodando **em paralelo** ao styled-components. Dois motores de CSS-in-JS
no mesmo app é pior que o problema original — e o benefício não justifica: o site usa 11 componentes,
7 dos quais são triviais.

**Encapsular é a etapa 1 do caminho, não o destino.** Sequência proposta:

**Fase 0 — Estancar o sangramento (1 dia, risco zero visual)**

1. Trocar `import * as AntIcons` (`src/common/Icon/index.tsx:1`) por um mapa explícito dos ícones
   realmente usados em `src/pages/Projects/data.json`:

   Ganho esperado: 150-250 KB de JS.
2. Adicionar `<link rel="preload" as="font" type="font/woff2" crossorigin>` em `index.html` e converter

3. Converter `contact-us.png` (287 KB) para AVIF/WebP com `srcset` (~25 KB).
4. Rodar SVGO em `brasil.svg` (32 KB → ~2 KB) e nas 4 ilustrações.

**Fase 1 — Encapsular (1 semana)**

5. Criar `src/styles/tokens.ts` (§3.3) e envolver a app num `<ThemeProvider theme={lightTheme}>` em
   `src/index.tsx`. Nenhum componente muda ainda.
6. Criar `src/common/Grid/` com `<Row>`/`<Col>` próprios em CSS Grid, com **API compatível**
   (`span`, `lg`, `md`, `sm`, `xs`, `justify`, `align`) para que a substituição seja um

7. Substituir os 4 componentes triviais: `Layout.Content` → `<main>`; `Card` → `src/common/Card/`;

**Guarda-corpo:** adicionar ao CI um orçamento de bundle (`rollup-plugin-visualizer` + falha se
`dist/assets/*.css` > 25 KB gzip) para a regressão não voltar por importação acidental.

## 3.3 Design tokens propostos

Arquivo a criar: **`src/styles/tokens.ts`**. Consumido via `ThemeProvider` do styled-components e
espelhado em CSS custom properties (para o antd durante a transição e para o tema escuro sem re-render).

### 3.3.1 Racional da paleta

A marca hoje tem um azul-marinho profundo (`#18216d`) que **funciona** — é sério, técnico, não é o
azul-SaaS genérico (`#1890ff`, `#0070f3`). A proposta o preserva como âncora e resolve o resto:

- **Ink (primária)** — escala construída a partir de `#18216d` como `ink-800`. É a cor da marca, de
  superfícies escuras e de texto de alta ênfase.
- **Amber (acento/ação)** — `#f59e0b`. Substitui `#ff0000` no papel de "ação e hover". Âmbar sobre
  azul-marinho é um par de alto contraste (complementar quente/frio), lê como "engenharia/energia" e
  **não** colide com erro. Também é uma escolha culturalmente ancorada: azul + amarelo é a leitura
  brasileira sem cair no clichê verde-e-amarelo de bandeira.
- **Danger** — `#dc2626`. Vermelho **dessaturado**, exclusivo para erro/destrutivo. Libera o `#ff0000`.
- **Neutros 50→900** — escala fria (matiz ~220°) para harmonizar com o ink. Resolve os 6 cinzas de §3.1.1.
- **Success / Warning / Info** — para os estados que hoje vêm do antd.

Todos os pares texto/fundo listados como `text.*` sobre `bg.*` foram escolhidos para **≥ 4.5:1**
(WCAG AA) e os de heading para **≥ 7:1** (AAA).

## 3.5 Direção de arte

### 3.5.1 O problema a resolver

O visual atual é indistinguível de qualquer template de landing page: ilustrações flat coloridas,
azul genérico, ilustração à esquerda + texto à direita alternando. Um comprador de software que já
viu 40 sites de agência esse mês não vai lembrar deste.

E o oposto — o "site premium genérico" (fundo preto, gradiente roxo/azul, glassmorphism, blob 3D
girando) — é igualmente esquecível desde 2022. Todo mundo faz.

**A tese:** para uma agência de dev brasileira parecer premium sem parecer genérica, a diferenciação
não vem de efeito visual, vem de **densidade de informação com composição tipográfica editorial**.
Consultorias de elite (a referência mental é publicação técnica impressa, não SaaS template) parecem
caras porque mostram trabalho real, com precisão, num grid rigoroso. Ilustração alegre é o oposto disso.

### 3.5.2 Conceito: "Engenharia visível"

Três princípios operacionais:

**1. O artefato é o herói.** A imagem principal de cada seção não é uma metáfora, é o **produto real**:
um trecho de código com syntax highlight, um diagrama de arquitetura, um dashboard de latência, uma
tela de app entregue. `prismjs` já está no `package.json` (usado em `src/pages/Post/index.tsx:5`) —
está pago, use na home. Nada convence um CTO como ver código bem escrito.

**2. Grid explícito.** Linhas de grid de 1px em `border.subtle` visíveis nas divisões de seção, réguas
verticais no container, âncoras de seção numeradas em mono (`01 / SERVIÇOS`). Isso comunica precisão
de engenharia como linguagem visual, e é praticamente inexistente em sites de concorrentes brasileiros.

**3. Contraste de densidade.** Alternar seções muito densas (grid de 6 badges de stack, tabela de
comparação) com seções muito respiradas (uma frase de 60px sobre fundo escuro). O ritmo denso/vazio é
o que separa design editorial de "conteúdo empilhado".

### 3.5.3 Fotografia vs ilustração vs 3D — decisão

| Meio | Veredito | Racional |
|---|---|---|
| **Ilustração flat** (o que existe hoje) | **Eliminar** | `developer.svg`, `graphs.svg`, `product-launch.svg`, `waving.svg` são stock reconhecível. Sinalizam "template", que é exatamente o oposto da mensagem. |
| **UI real / screenshots de produto** | **Principal — 60% do peso visual** | Telas dos projetos entregues, em mockups de device minimalistas (frame de 1px, sem sombra de laptop realista). Se houver NDA, blur seletivo com o padrão de grid por cima — o blur em si vira elemento gráfico e sinaliza "clientes sérios". |
| **Código como imagem** | **20%** | Snippets reais com `prismjs`, tema custom nos tokens do design system (não `prism.css` default). Em `bg.inverse`, mono 13px/1.7, com barra de janela minimalista. |
| **Diagramas técnicos autorais** | **15%** | Arquitetura de solução em SVG, traço 1.5px em `border.strong`, nós em `bg.surface`, fluxo destacado em `accent.default`. Feitos à mão no estilo da marca — impossível de confundir com stock. |
| **Fotografia de pessoas** | **5%, e só se for real** | Foto verdadeira da equipe na página "Sobre" — tratamento consistente (mesma luz, mesmo fundo, leve dessaturação, grade uniforme). **Nunca** stock de "equipe diversa sorrindo em open space". Stock de pessoas destrói mais credibilidade do que a ausência de foto. |
| **3D / render** | **Evitar** | O blob 3D metálico é a marca registrada do template premium de 2023. Única exceção admissível: um objeto 3D **autoral e recorrente** que vire a marca gráfica (ver abaixo) — mas isso é investimento de identidade, não decoração de landing page. |

**Marca gráfica proposta:** o wordmark `lemamon.dev` em mono, com o `.dev` em `accent.default`, e um
símbolo derivado de um **cursor de terminal** (um retângulo cheio) que pisca sutilmente em pontos
específicos da interface (fim do headline do hero, ao lado do CTA final). Um único elemento,
reconhecível, barato de produzir, coerente com a categoria, e não é um blob.

### 3.5.4 Grid e densidade

- **Grid:** 12 colunas, gutter `spacing[6]` (24px) desktop / `spacing[4]` (16px) mobile,
  container `1200px` com `layout.gutter` de 40/32/20px.
- **Composições permitidas:** `12`, `6+6`, `7+5`, `8+4`, `4+4+4`, `3+3+3+3`. **Proibido** `11+11`
  com `space-between` — que é exatamente o que `ContentBlock/index.tsx:59,62` faz hoje (dois `Col lg={11}`),
  produzindo uma calha central de largura arbitrária que não pertence a nenhum grid.
- **Medida de leitura:** máximo `68ch` (`layout.container.prose`). Hoje o `<p>` global tem 21px
  (`styles.ts:75`) dentro de um container de 1200px sem `max-width` de texto — linhas de ~100 caracteres,
  bem acima do limite de legibilidade (45-75).
- **Densidade:** hero respirado (`sectionSpacing.spacious`), seções de prova densas
  (`sectionSpacing.compact`), CTA final respirado. Alternância deliberada, não uniforme como hoje
  (todo `ContentBlock` tem `padding: 4rem 0`).

### 3.5.5 Motion

Regra geral: **o movimento serve à orientação, não ao espetáculo.** Todo movimento em
`duration.fast` ou `normal`; nada acima de `600ms`.

- **Reveal de seção:** `opacity 0→1` + `translateY(16px→0)`, `duration.slower`, `easing.out`,
  stagger de 60ms entre irmãos, `IntersectionObserver` com `threshold: 0.15`, **dispara uma vez**.
  Substitui `react-awesome-reveal` (32 KB) por ~15 linhas.
- **Hover de card:** `translateY(-4px)` + `shadow.md→lg`, `duration.normal`. Só sob `media.hover`
  (não disparar em touch).
- **Cursor do terminal:** `opacity` piscando a 1.06s, `steps(2)`. Um por viewport, no máximo.
- **Barra de progresso do wizard:** `width`, `duration.slow`, `easing.inOut`.
- **Header:** ao passar de 80px de scroll, encolher `padding` de `spacing[4]`→`spacing[3]` e adicionar
  `shadow.sm` + `backdrop-filter: blur(12px)` com `bg.canvas` a 80% de opacidade. `duration.normal`.
- **`prefers-reduced-motion: reduce`:** desliga marquee, reveal e parallax; mantém transições de cor
  (que orientam) reduzidas a `0.01ms`.

### 3.5.6 Voz visual brasileira, sem clichê

Não usar verde-e-amarelo de bandeira, nem folhagem tropical, nem as três bandeirinhas de idioma
atuais (`Footer/index.tsx:79-101` — `brasil.svg` de 32 KB, `spain.svg`, `united-states.svg`;
bandeira ≠ idioma, e "United States" para inglês exclui o resto do mundo anglófono).
Substituir por um seletor textual: `PT · EN · ES`.

O que sinalizar em vez disso: **"Florianópolis, SC"** já está no footer (`Footer/index.tsx:73`) e é um
ativo real — Floripa tem reputação de polo de tech. Colocar no hero, não escondido no rodapé.
Fuso horário compatível com os EUA (`GMT-3`, sobreposição de 6h com a costa leste) é argumento
comercial concreto para nearshore e merece uma linha na home.

### 3.6.1 Comportamento responsivo — regras transversais

| Faixa | Grid | Tipografia h1 | Gutter | Ritmo de seção |
|---|---|---|---|---|
| `< 640px` | 1 col | 40px | 20px | `compact` |
| `640-767px` | 1-2 col | 44px | 24px | `compact` |
| `768-1023px` | 2 col | 48px | 32px | `default` |
| `1024-1279px` | 12 col | 60px | 40px | `default` |
| `≥ 1280px` | 12 col, container 1200px | 72px | 40px | `spacious` |

- Alvo de toque mínimo 44×44px em todo elemento interativo abaixo de `md`.
- Nada de `100vh` em mobile — usar `100svh` ou altura automática.
- Toda imagem com `width`/`height` intrínsecos + `aspect-ratio` para CLS = 0.
- `Section` full-bleed no fundo, container interno para o conteúdo — evita scroll horizontal e o
  `overflow-x: hidden` de `src/styles/styles.ts:31`, que hoje é um curativo escondendo o sintoma.
